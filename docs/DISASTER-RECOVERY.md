# خطة استمرارية الأعمال والتعافي من الكوارث (DRP)

## الأهداف
| المؤشر | الهدف |
|---|---|
| RPO (أقصى فقد مقبول للبيانات) | ≤ 24 ساعة (نسخ يومي) — وعملياً دقائق مع PITR لدى Neon |
| RTO (أقصى زمن توقف) | ≤ 4 ساعات |
| العمل الميداني أثناء الانقطاع | مستمر عبر وضع عدم الاتصال في التطبيق (حتى 24 ساعة) |

## 1. أثناء انقطاع الإنترنت أو الخادم (المطبخ)
1. يستمر الطهاة بتعبئة النماذج من التطبيق: تُحفظ السجلات على الجهاز بوقت القياس الفعلي.
2. تظهر في الرئيسية: «X سجل بانتظار الاتصال».
3. عند عودة الاتصال تُرسل تلقائياً (كل 30 ثانية أو فوراً عند عودة الشبكة) دون تكرار.
4. **أي قراءة خارج الحد الحرج أثناء الانقطاع:** ينفّذ الطاهي الإجراء الفوري المعروض على الشاشة ويبلّغ المشرف شفهياً — يُفتح CAPA تلقائياً عند المزامنة.
5. إذا تجاوز الانقطاع 24 ساعة: تُرفض السجلات الأقدم (حماية من التلاعب بالتواريخ) وتُعاد يدوياً مع ملاحظة.

## 2. النسخ الاحتياطي
### بيئة Vercel + Neon (التجربة الحالية)
- Neon يوفر **Point-in-Time Restore** (حسب الخطة) — الاستعادة من لوحة Neon ← Branches ← Restore.
- قبل أي تعديل كبير: `pg_dump "$DATABASE_URL" -Fc -f backup-$(date +%F).dump`

### بيئة VPS داخل المملكة (الإنتاج الموصى به)
`docker compose up -d` يشغّل خدمة `db-backup` التي تأخذ نسخة يومية مضغوطة إلى `./backups` وتحتفظ بآخر 14 يوماً.
**يجب** نسخ مجلد `backups/` إلى موقع ثانٍ (خادم آخر أو تخزين سحابي داخل المملكة).

### مفتاح التشفير `DATA_ENCRYPTION_KEY`
- يشفّر أرقام الهوية/الإقامة. **فقدانه = استحالة فك تشفير هذه الحقول.**
- يُحفظ في خزنة كلمات مرور الشركة بشكل منفصل عن النسخ الاحتياطية.

## 3. الاستعادة
```bash
# 1) قاعدة بيانات جديدة فارغة ثم:
pg_restore --no-owner -d "$DATABASE_URL" backup-YYYY-MM-DD.dump
# 2) تشغيل الترحيلات (لا تعيد تطبيق ما سبق تطبيقه):
cd backend && npm run db:migrate
# 3) ضبط المتغيرات (نفس JWT_SECRET و DATA_ENCRYPTION_KEY) ثم تشغيل الـ API والتحقق:
curl https://<domain>/health   # {"status":"ok","database":"up"}
```

## 4. سيادة البيانات
بيئة التجربة الحالية (Vercel + Neon) مستضافة خارج المملكة. للتشغيل الرسمي ولمتطلبات الهيئة الوطنية للأمن السيبراني (NCA) ونظام حماية البيانات الشخصية (PDPL) يُنصح بنشر `docker-compose.yml` على خادم داخل المملكة (مثل مراكز بيانات STC Cloud أو Oracle Jeddah/Riyadh أو Google Cloud Dammam) دون أي تعديل على الكود.

## 5. اختبار الخطة
- اختبار استعادة نسخة احتياطية: **كل ربع سنة**، ويوثّق في `documents` كسجل.
- تمرين انقطاع الشبكة في المطبخ: **كل 6 أشهر** للتأكد من مزامنة السجلات.
